# YAK Decoder 2.x — устройство проекта

Справочник для сопровождения текущей ветки. Все пути указаны относительно корня проекта; пользовательская инструкция — в [README.md](README.md), ресурсы — в [LIMITS.txt](LIMITS.txt).

## Совместимость и запуск

- Интерфейс: 0.10 (`public/index.html`). Номер приложения не связан с номером PHP или YAK Pro.
- Декодируемый синтаксис: PHP 7.4; обфускатор в проверках — YAK Pro 2.0.17.
- Парсер: включённый PHP-Parser 4.19.4. Подмена на PHP-Parser 5 требует отдельной адаптации.
- Комплект: PHP 7.4.33 NTS VC15, Windows x64; происхождение и лицензии — `runtime/`.
- `start.cmd` запускает сервер на `127.0.0.1:18090` с DocumentRoot `public/`.

На Windows CLI берётся из `runtime/php/php.exe`, при его отсутствии — из `YAK_PHP_BINARY`, затем `PHP_BINDIR`. Декодирование и lint используют один CLI с `-n`.

## Обработка запроса

Браузер отправляет код на `decode.php`; endpoint проверяет запрос и передаёт текст отдельному worker. Worker разбирает AST и восстанавливает структуру. Затем DecoderProcess проверяет выходной PHP через `php --syntax-check`. Только после успешного lint возвращается `syntaxChecked: true`. Временные файлы и буферы удаляются.

Входящий PHP нельзя выполнять, подключать через include/require или eval. Для работы декодера исполняется только собственный worker. Lint проверяет синтаксис, а не поведение программы.

### HTTP-контракт

POST `decode.php`, Content-Type `application/json`:

```json
{"code":"<?php ...", "requireYakSignature":false, "completeFile":false}
```

- `code`: непустая строка до 5 МиБ; JSON-тело — до 32 МиБ.
- Два необязательных флага имеют тип boolean и по умолчанию равны false.
- `requireYakSignature` требует точного вхождения `Obfuscated by YAK Pro - Php Obfuscator`.
- `completeFile` сохраняет режим смешанного HTML/PHP; пакетный интерфейс передаёт true. В режиме фрагмента при необходимости добавляется открывающий PHP-тег. UTF-8 BOM удаляется.
- Успех: `ok:true`, `code`, `gotoBefore`, `gotoAfter`, `syntaxChecked:true`.
- Ошибка: `ok:false`, `error`; при отсутствии подписи — `errorCode:yak_signature_missing`.
- Ошибки: 400 — формат/типы, 405 — метод, 413 — размер, 415 — Content-Type, 422 — код/подпись/выходной синтаксис. Сбой worker возвращает 500, ошибка запуска или ресурсов может возвращать 503.

Счётчики используют T_GOTO: строки и комментарии с текстом `goto` не считаются переходами. Чистый PHP также проходит форматирование, поэтому побайтовая сохранность текста не обещается.

## Пакетные результаты

Файлы обрабатываются последовательно. Проверки путей запрещают абсолютные пути, `..`, дубликаты и конфликты файлов с папками. ZIP формируется в браузере; исходные файлы не перезаписываются.

| Статус | Результат в ZIP |
|---|---|
| `decoded` | Проверенный PHP без goto |
| `partial` | Проверенный PHP с оставшимися goto |
| `kept` | Исходные байты: другой тип, пустой файл, нет PHP-тегов или нужной подписи |
| `warning` | Исходные байты: больше 5 МиБ или не UTF-8 |
| `error` | Исходные байты: ошибка обработки или lint |
| `directory` | Запись папки |

При `partial`, `warning` или `error` добавляется текстовый отчёт с тремя разделами, путями и причинами. Имя выбирается без коллизий и учитывается в лимите записей ZIP. Отмена или транспортная ошибка прекращают обработку без сборки архива. Статистика считает файлы, а не переходы.

## Правила изменения декодера

1. Сравнивайте поведение с обфусцированным входом: исходник до YAK может иметь другую семантику.
2. Сохраняйте payload-проверки и `keptGotosAreStable`: они защищают от потери узлов, дублирования и переходов к удалённым меткам.
3. Передавайте цели внешних break/continue вложенным телам. Try/catch/finally не увеличивают глубину; циклы и switch увеличивают. У for целью continue может быть блок инкремента.
4. Не передавайте контекст через границы функций, методов и замыканий. Перед новой попыткой региона удаляйте устаревшие `deob_controls`.
5. Новую ошибку воспроизводите безопасной минимальной программой, затем проверяйте lint, число goto, stdout/stderr и код возврата на разных входах.

Команды проверки приведены ниже. `tests/diag.php` показывает статистику, отказы и трассировку; дамперы в `tests/` помогают исследовать CFG. `tests/scratch/` содержит вспомогательные инструменты с явными параметрами путей, для запуска сайта они не нужны. Сценарии сравнения поведения допустимы только для известных безопасных тестовых файлов.

## Проверки

Команды выполняются из корня проекта. Для Python-проверок нужен Python, для пакетных — Node.js.

```text
powershell -NoProfile -ExecutionPolicy Bypass -File tests/final_check.ps1
python tests/portable_runtime_test.py
python tests/cases/stress-b-php74/run_tests.py
```

Первая команда проверяет базовые регрессии, вторая сама запускает и останавливает сервер, третья проверяет сохранённые 50 стресс-вариантов. Для создания свежих обфускаций у третьей команды есть параметр `--yakpro ПУТЬ/К/yakpro-po.php` (нужен YAK Pro 2.x).

Для проверки пакетного режима сначала запустите сайт через `start.cmd`, затем:

```text
node tests/batch_test.js "%TEMP%/yak-batch-check"
python tests/verify_batch_zip.py "%TEMP%/yak-batch-check"
```

Стресс-проверки исполняют только специально подготовленные тестовые программы. Сайт пользовательский PHP не исполняет.

## Ограничения

Неподдержанный граф сохраняется частично; отсутствие goto не гарантируется для произвольного PHP. В `crosslevel-test.php` намеренно остаются три перехода — это проверка безопасного отката. Успешные тесты других файлов нельзя выдавать за универсальную гарантию.

Обфускатор YAK Pro 2.0.17 в включённом примере меняет `do/continue`: `doWhileLoop(2)` даёт `[2,[1]]` до обфускации и `[3,[1,3]]` после неё. Декодер сохраняет второй результат. Изначальные имена переменных и функций не восстанавливаются без дополнительной информации.
