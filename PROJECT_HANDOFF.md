# YAK DECODER — контекст для доработки проекта

## Версия интерфейса

Текущая версия — **0.10**. Формат номера: `0.xx`; следующие версии — `0.11`, `0.12` и далее. Номер отображается в верхней панели сайта рядом с `PHP → PHP`, в `public/index.html`. При выпуске следующей версии синхронно обновляйте номер в интерфейсе и этом разделе. Номер приложения не связан с версией PHP или YAK Pro.

Этот документ описывает проект и его текущее устройство. Это справочная информация для нового разработчика или ИИ-агента, а не новое задание: конкретные изменения определяет запрос пользователя. Перед доработкой сверяйте сведения с актуальными файлами.

## Назначение

Локальный сайт для восстановления читаемой структуры PHP-кода после YAK Pro: переходы `goto` и метки преобразуются в условия и циклы, насколько это позволяет анализ потока управления. Поддерживаются одиночный фрагмент и рекурсивная пакетная обработка папки модуля OpenCart с выдачей ZIP.

Целевая версия обфускатора — ветка **2.x**: https://github.com/pk-fr/yakpro-po/tree/2.x . Проверки выполнялись с YAK Pro 2.0.17. Поддержка ветки master, использующей PHP-Parser 5, отдельно не заявлена. В самом декодере включён PHP-Parser 4.19.4. Это собственный декодер кода YAK Pro, а не сам обфускатор.

## Расположение файлов

Все пути ниже указаны относительно корня распакованного проекта. Сайт автономен: использует включённые в комплект декодер, PHP-Parser и PHP runtime. Внешние рабочие папки автора не нужны.

## Запуск и зависимости

Локальный порт сайта — **18090**. Адрес: `http://127.0.0.1:18090/`. Порт запуска и адрес, открываемый в браузере, задаются в `start.cmd`; при их изменении синхронно обновляйте README и примеры команд в документации.

На Windows x64 распаковать комплект целиком и запустить `start.cmd`. Открывается `http://127.0.0.1:18090`; окно сервера должно оставаться открытым. Остановка — Ctrl+C.

В `runtime/php/` включён **PHP 7.4.33 NTS VC15 Windows x64**, необходимые DLL Visual C++ и лицензии. Устанавливать PHP, Composer, Node.js или Python для обычной работы не требуется. Происхождение компонентов записано в `runtime/manifest.json`. Не удаляйте runtime и лицензии при переносе.

`start.cmd` проверяет версию PHP и запускает сервер с корнем `public/`. Флаг `-n` исключает влияние системного php.ini. Для другого сервера DocumentRoot также должен указывать на `public/`, нужен доступ к PHP CLI и разрешённая функция `proc_open`. На Windows встроенный PHP имеет приоритет; при его отсутствии путь CLI задаётся `YAK_PHP_BINARY`, затем используется PHP_BINDIR. Windows runtime нельзя запускать на Linux.

## Поток одиночной обработки

1. Браузер отправляет POST JSON на `decode.php`.
2. Endpoint проверяет метод, тип содержимого, размер и типы параметров, при необходимости подпись YAK Pro.
3. `DecoderProcess` передаёт код через STDIN отдельному процессу `worker.php`.
4. Worker разбирает PHP в AST и вызывает `Deobfuscator::processFile`.
5. После декодирования выходной код обязательно проверяется отдельным запуском **php --syntax-check**, эквивалентом **php -l**, на временном файле.
6. Только успешная проверка позволяет вернуть `syntaxChecked: true`. Результат заменяет текст в том же textarea; доступно восстановление исходника. При ошибке исходник остаётся.

Входящий PHP **не исполняется**: его нельзя подключать через include/require, eval или запускать как программу. Выполняется только собственный worker приложения; php -l проверяет синтаксис. Lint не гарантирует правильность логики или наличие зависимостей OpenCart.

Без goto и меток PHP проходит через парсер и форматирование; отступы, переносы и запись строк могут измениться. Имена переменных, переименованных обфускатором, автоматически не восстанавливаются.

## HTTP-контракт

POST `public/decode.php`, Content-Type `application/json`:

```json
{"code":"<?php ...", "requireYakSignature":false, "completeFile":false}
```

- `code`: непустая строка, максимум 2 МиБ UTF-8; JSON-тело ограничено 8 МиБ.
- `requireYakSignature`: необязательный boolean, по умолчанию false.
- `completeFile`: необязательный boolean, по умолчанию false. Включается пакетным режимом, чтобы не добавлять PHP-тег перед смешанным HTML/PHP (например, TPL).
- В режиме фрагмента worker удаляет UTF-8 BOM и добавляет `<?php`, если в начале нет PHP-тега.
- Успех: `ok`, `code`, `gotoBefore`, `gotoAfter`, `syntaxChecked`.
- Ошибка: `ok:false`, `error`; отсутствие обязательной подписи также даёт `errorCode: yak_signature_missing`.
- Проверка подписи — точное регистрозависимое вхождение `Obfuscated by YAK Pro - Php Obfuscator` в любом месте. Версия, дата и оформление комментария не учитываются. Это фильтр, а не подтверждение подлинности.
- Счётчики goto используют T_GOTO, а не поиск подстроки в комментариях или строках.

Процесс декодирования ограничен 512 МиБ памяти, примерно 25 секундами и 16 МиБ ответа. Проверка синтаксиса — 5 секунд. Временные файлы очищаются. В браузере запрос пакетного файла ограничен 35 секундами.

## Пакетная обработка

Папка добавляется **только перетаскиванием**. Кнопка выбора папки удалена по требованию пользователя. Обход использует webkitGetAsEntry и повторные readEntries, включая вложенные и пустые папки.

`batch-core.js` сохраняет исходные пути вместе с именем корневой папки. Обрабатываются `.php`, `.php0`–`.php9`, `.phtml`, `.inc`, `.tpl`, если есть PHP-теги. Запросы выполняются последовательно через тот же endpoint с completeFile=true. Флаг подписи общий для одиночного и пакетного режимов.

Остальные файлы копируются побайтно, включая изображения, XML, Twig, CSS, JS и скрытые файлы. Если подпись обязательна, файлы без неё копируются без изменений. Исходная папка на диске не изменяется. На сервер передаётся подходящий PHP-код, а не пути для извлечения файлов.

ZIP собирается в браузере собственным кодом, без внешних библиотек: STORE без сжатия, UTF-8 имена, CRC32, записи папок. Проверки путей запрещают traversal, абсолютные пути, коллизии файлов/папок и дубликаты. Лимиты: 5000 файлов, 10000 записей ZIP, 100 МиБ входа, 150 МиБ результатов декодирования. Добавление отчёта также учитывается в лимите записей ZIP.

### Статусы и статистика

| Статус | Смысл | Что сохраняется в ZIP |
|---|---|---|
| decoded | Декодирование успешно, goto не осталось | Результат после lint |
| partial | После обработки остались goto | Частичный результат после lint |
| kept | Обработка не требуется или не допускается фильтром | Исходные байты |
| warning | PHP больше 2 МиБ или не UTF-8 | Исходные байты с пояснением |
| error | Ошибка декодера или проверки результата | Исходные байты с пояснением |
| directory | Запись папки | Папка |

Счётчики в итоговой статистике считают **файлы**, а не число goto. Дополнительно показаны папки, время и размер ZIP. Журнал автоматически прокручивается к новой строке. Отмена прекращает сборку; при сетевой ошибке обработка прерывается без архива. Ошибка отдельного файла сохраняет исходник и позволяет продолжить.

Если есть partial, warning или error, `buildZip` добавляет в корень архива **yak-decoder-report.txt**: три секции с количеством, полными относительными путями и пояснениями. Если всё успешно, отчёта нет. При совпадении имени выбирается вариант с числовым суффиксом, исходный файл не перезаписывается. Отчёт не включается в счётчики исходных файлов интерфейса.

Светлая серо-голубая палитра с бирюзовыми кнопками, ориентированная на SiteUpgrade. Подпись чекбокса и его пояснение — 16px. Исследовательские материалы автора в комплект проекта не входят.

## Известные ограничения и исторические результаты

Историческая база: набор из 72 реальных PHP-файлов преобразовывался без оставшихся goto и с успешным lint; базовое покрытие if/else/elseif/for/while/do проверялось на 25 случайных вариантах максимального запутывания YAK Pro. Это результаты конкретных наборов, не гарантия для любого файла.

Текущая версия дополнительно покрывает вложенные циклы с break 2/continue 2, switch внутри цикла, циклы внутри switch и тройное вложение с break 3/continue 3. Включённый пример `examples/stress-yak-obfuscated.php` декодируется до 0 goto с выводом, идентичным обфусцированному входу (дифференциальные тесты на серии seed'ов и на независимых повторных обфускациях `examples/stress-original.php`; раньше этот случай оставлял все 403 goto — устранено). Ранее воспроизводившийся fallback «multiple loop exits» на вложенном управлении потоком устранён; неподдержанные случаи всё равно корректно откатываются с сохранением goto.

Обнаружено изменение поведения самим YAK Pro для do/continue: декодер должен сохранять поведение полученного обфусцированного кода, а не автоматически исправлять обфускатор. Пример: `doWhileLoop(2)` возвращает `[3,[1,3]]` и в обфусцированном, и в декодированном виде.

Остаточные ограничения: пользовательские goto между структурами одного уровня (не-шаблонные для YAK) обрабатываются консервативно — регион откатывается к исходной форме, чтобы не осиротить метки. При работе с CFG чувствительны побочные эффекты условий циклов, точки слияния ветвей и недостижимый код; проверки сохранности узлов AST (payload) и откат региона нужны для защиты от потери или дублирования логики — не отключайте их ради нулевого счётчика goto. Не считайте исчезновение goto само по себе доказательством корректности — доказательством является только дифференциальное сравнение поведения с обфусцированным входом.

Мёртвый шаблонный путь (unshuffle/build/rebuildShuffled/detectLoop и связанные методы/свойства) удалён 2026-11-02; актуальная реализация восстановления структуры — CFG-подход в CfgStructurer (доминаторы, регионы, for-эмиссия, многоуровневый break/continue). Подробности и диагнозы — в `HANDOFF_DECODER_FIXES.md` в корне проекта.

PHP 7.4.33 выбран пользователем специально. Поддержка PHP 8 или PHP-Parser 5 требует отдельной проверки совместимости, а не простой замены бинарника или vendor.

2. **Контролы не доходили до вложенных foreach**: attachNativeControls вызывался только для statements, лежащих в блоке напрямую; foreach внутри if/else не-циклических ветвей никогда не получал отображение «метка → break/continue N», а метки этих блоков при эмиссии исчезают. Фикс: `attachNestedControls()` в CfgStructurer — спуск по под-дереву statement (через if/else/try, не пересекая функции/замыкания и тела циклов) с подсчётом bias (пересекаемые циклы смещают глубину break/continue) и учётом хвостового положения (последний statement ветви → переход на «следующий блок» = break 1).

Валидация фикса: stress 403→0, фикстуры, example.txt, crosslevel, чистый исходник — без изменений (22/22); оба `social_login.php` — 1925→0, converted=69/kept=0; весь корпус DEOB (72 файла) — php -l чисто, 0 goto, дифференциальное сравнение поведения (CLI-запуск с 512М) — 0 расхождений; HTTP 28/28.

### Где выявлено изменение поведения самим YAK Pro

Включённая пара `examples/stress-original.php` и `examples/stress-yak-obfuscated.php` воспроизводит расхождение: функция исходника `doWhileLoop(2)` возвращает `[2,[1]]`, а соответствующая функция после YAK Pro 2.0.17 — `[3,[1,3]]`. В исходнике это do-цикл с continue при i === 2. В оригинале continue ведёт к проверке условия; обфусцированный переход пропускает её и начинает следующую итерацию.

Минимальный исходный пример того же случая:

```php
<?php
$i = 0;
$trace = [];
do {
    $i++;
    if ($i === 2) {
        continue;
    }
    $trace[] = $i;
} while ($i < 2);
echo json_encode([$i, $trace]), "\n";
```

До обфускации: `[2,[1]]`. В исследованном результате YAK Pro 2.0.17: `[3,[1,3]]`. Это наблюдение о конкретном тесте и версии, не утверждение обо всех версиях YAK Pro. Декодер должен сохранять поведение полученного обфусцированного файла; восстановление поведения исходника до обфускации — отдельная задача.
