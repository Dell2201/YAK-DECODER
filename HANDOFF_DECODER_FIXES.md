## Диагноз (почему было «403 goto остаются все»)

Это был **не** отказ декодера по всему файлу, а каскадное отбрасывание успешной работы:

1. Весь код файла лежит в одном namespace → `processNested` обрабатывал тело namespace как один регион (функции + main-цикл).
2. Эмиссия региона **успешалась**, внутри неё конвертировались 20+ вложенных тел (включая simpleIf и main-цикл).
3. Две функции реально отказывали с `multiple loop exits` (см. ниже).
4. Финальный `hasGotoOrLabel($result)` в `processBody` видел остатшиеся goto этих тел и **выбрасывал всё** — возврат к нетронутому оригиналу уничтожал все успешные конвертации. Отсюда иллюзия «не конвертируется даже simpleIf».

## Исправления

### Deobfuscator.php (Task 1 — каскадное отбрасывание)

- **Nested-first**: вложенные тела конвертируются до эмиссии региона; их результат переживает любой отказ региона (в т.ч. `return $original` в catch теперь возвращает дерево с уже конвертированными вложениями).
- Проверка «has-goto» заменена на корректный критерий `keptGotosAreStable`: реструктурировать регион можно, если остатшиеся goto лежат в независимо оставленных телах и их метки стабильны (учёт kept-скоупов через `$scopeStack`); прыжок оставленного тела на метку самого региона → откат региона к исходной форме (предохранитель от «осиротевших» goto — метки уровня региона при реструктуризации исчезают, `php -l` это не ловит, это runtime fatal).
- Попытки pre-walk — «тихие» (не пишут в failures/stats); одиночные goto-списки не пытаются вовсе (конвертируемы только с контролнами региона).
- `seedControls`: для «голой» попытки тела foreach хвостовая метка тела сеется как `continue 1` (без этого `continue 2` без `break 2` молча конвертировался неверно — ловится дифференциальным тестом).
- Диагностика: `$trace` (контекст/исход/причина по телам), детализированное сообщение payload-mismatch.

### CfgStructurer.php (Task 2 — `multiple loop exits`), 4 независимых дефекта

1. **Сырой fall-through в `emit()`** — `$cur = $cur->fall` не резолвил пустые goto-алиасы → эмиция попадала на фантомные блоки вне узлов цикла → ложный второй выход. Заменено на `resolveBlock($cur->fall)`. (Одно это починило `switchAndLoop`/`gdv_3K9UzFUjqr0X`.)

2. **Эмиссия `for` с latch-блоком** — если ровно один выделенный блок-инкремент является единственным внутрицикловым предшественником заголовка, цикл эмитится как `for (; cond; incr)`. Тогда `continue N` из вложенных циклов (прыжок на инкремент) выражается корректно, без дублирования инкремента. Инвариант «единственный latch» гарантирует семантику: YAK опускает `continue` while-циклов в условие (→ второй предшественник → for-форма не выбирается), а `continue` for-циклов — в инкремент (→ for-форма). Паттерн выбирает себя сам. Бонус: `forLoop` вернул форму исходника. Внимание: в php-parser 4.x `Stmt\For_` принимает массив subnodes (`new Stmt\For_(['init'=>…, 'cond'=>…, 'loop'=>…, 'stmts'=>…])`), а не позиционные аргументы — в мёртвом шаблонном коде `build()` была та же ошибка.

3. **Многоуровневый `break N`/`continue N`** (`loopControl`) — прыжки из цикла сверяются с цепочкой родительских циклов: заголовок с условием → `continue N`; for-инкремент (`continueBlock`) → `continue N`; exit родителя → `break N`; цели в середине тела родителя остаются выразимыми как собственный единственный выход цикла (break + fall-through). Подключён к обоим сайтам: goto-переход **и** fall-прибытие (продолжение `continue 2` через ветвление попадает в emit() вторым путём — это был отдельный баг).

4. **Extension-walk в `findLoops` выполняется всегда** — раньше пропускался, когда у цикла не находился внутрирегионный exit. У циклов в телах switch-кейсов выходы уходят в OUTER-контролы (строки `'OUTER:…'`) → exit === null → пути continue/break не попадали в узлы цикла. Это чинит все кейс-регионы.

Дополнительно: diagnostic-контекст в `multiple loop exits` (какие блоки конфликтуют), флаг `hasHeaderCond` у цикла (do-while нельзя продолжать через заголовок).

## Остаточные ограничения (намеренные)

- **YAK-изменение поведения do/continue сохраняется** — декодер обязан сохранять поведение обфусцированного файла, а не восстанавливать исходник (см. PROJECT_HANDOFF, раздел про doWhileLoop). Пример: `doWhileLoop(2)` → `[3,[1,3]]` и в обфусцированном, и в декодированном.
- Пользовательские goto между структурами (не-YAK паттерн, например прыжок из одного if-тела в другое) — теоретическая дыра, унаследованная от прежнего кода; предохранитель откатывает регион консервативно.
- Мёртвый шаблонный путь в Deobfuscator (`unshuffle`/`build`/`rebuildShuffled`/`detectLoop`/`labelIndex`/`target`/`jumpToLoopControl`/`lastMeaningful`/`negate` и свойства `alias`/`unresolved`/`failLabel`) **удалён 2026-11-02** (вызывался только сам из себя). Оставлен рабочий `isSingleGoto` (нужен `listNeedsWork`). Устранён и упоминавшийся здесь латентный позиционный вызов `Stmt\For_` в `build()`.
- `CfgStructurer::$placed` пишется, но не читается (безвредно).
- Поддержка PHP 8 / PHP-Parser 5 не заявлена (как и раньше).

## Регрессия на реальных файлах (DEOB) — найдена и исправлена 2026-11-02

Внешний агент проверил v2 на 72 реальных файлах (`C:\Users\Dell\Downloads\DEOB`): stress и синтетика зелёные, но в двух копиях `catalog/controller/extension/module/social_login.php` прежняя версия убирала все goto, а v2 оставляла 172. Воспроизведено; диагноз (диагностика `tests/diag.php` + трассировка processBody/attachNativeControls):

- Метод `sendSmsCode` содержал `goto srEbb` внутри двойного foreach (метка — вне тела, на уровне метода). Эмиссия метода строила верное отображение `srEbb=>break1` (сравнение с оригинальной библиотекой показало идентичность на этом уровне), но ретраи тел падали с `unknown jump target: srEbb`, а затем метод откатывался целиком по предохранителю `cross-level goto in kept nested body`.
- **Дефект 1 — протухшие deob_controls**: pre-walk (nested-first) конвертировал тело внешнего foreach до эмиссии объемлющего региона; та эмиссия навешивала на вложенные ещё-не-конвертированные foreach/switch АТРИБУТ со старым набором меток (без srEbb, не для этого уровня). При ретрае тело использовало протухший атрибут. Фикс: `Deobfuscator::stripStaleControls()` — сброс deob_controls перед каждой собственной попыткой региона (переданное отображение $controls остаётся).
- **Дефект 2 — контролы не доходили до вложенных foreach**: `attachNativeControls` вызывался только для statements, лежащих в CFG-блоке напрямую; foreach внутри if/else не-циклических ветвей вообще не получал отображения, а метки этих блоков исчезали при эмиссии. Фикс: `CfgStructurer::attachNestedControls()` — при эмиссии блока спуск по под-дереву statement (через if/elseif/else/try, не пересекая функции/замыкания и не вторгаясь в тела циклов — их конвертация добавляет уровень сама) с подсчётом bias (каждый пересечённый While_/For_/Do_ смещает глубину break/continue на 1) и флагом tail (последний statement ветви, исполняющийся последним на пути к следующему блоку: переход на «блок после» = break 1).

## Живой модуль OCMOD — дефект эмиссии latch-ветвления (исправлен 2026-11-03)

Внешний агент проверил v2 на живом модуле `C:\Users\Dell\Downloads\social_login-opencart-2.3-3.x-v4.0.236.ocmod` (290 PHP-файлов): 289 полностью, один частичный — `upload/system/library/social_login/TemplateFormatCleaner.php`, 78 → 21 goto, отказ «payload mismatch (loss or duplication)» с потерей `Expr_BinaryOp_NotIdentical`/`Scalar_String "."`.

Диагноз (фикстура из метода `isSafePath` + дампер CFG `tests/scratch/dump_cfg_method.php`): цикл обхода каталогов с условием продолжения в КОНЦЕ тела — latch-блок `iy2zg: if ($n9dvq !== ".") goto заголовок; else → return true`. При эмиссии тела `emitBranch()` на этом блоке получал M===null (merge постдоминаторов с виртуальным выходом не находит общего блока), а обе цели ветвления оказывались в stop-наборе (заголовок цикла + merge-блок внешнего if): emit() для обеих сторон возвращал ПУСТОЙ список, и ветвление с условием молча выбрасывалось — тело цикла превращалось в безусловный `return true`. Payload-проверка корректно отклоняла результат (страховка работает), но регион оставался с goto. Отдельно замечено: ключ `'OUT' => true` в stop-наборе — мёртвый след (isStop смотрит только id блоков).

Фикс в `emitBranch()` (CfgStructurer): (1) цель ветви = заголовок текущего цикла → сторона эмитится как `continue` (условная обратная дуга — это условный continue); (2) если после этого обе стороны пусты — отказ региона `branch with both arms stopped` вместо молчаливой потери условия.

Валидация: TemplateFormatCleaner — 78→0, converted=5/kept=0, `php -l` чисто; поведение идентично (13 кейсов `isSafePath` + путь из 40 сегментов, гоняющий цикл 40 итераций — harness `tests/scratch/cmp_tfc.php`); весь корпус OCMOD (290 файлов, включая два файла 2–2.3 МБ) — php -l чисто, 0 goto, 0 расхождений поведения; stress/фикстуры — без изменений; фикстура `tests/fixtures/tfc-latch-obfuscated.php` (реальный файл + самозапускаемый harness) добавлена в final_check — теперь 25 проверок.
